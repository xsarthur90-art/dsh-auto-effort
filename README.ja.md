# dsh-auto-effort · 強度の自動選択

もう強度は選ばなくていい。一度入れるだけで、**DeepSeek がメッセージごとに選びます**。

## 安く、速く、気楽に — コストが見えて、いつでも切り替え

![モデルメニューの「強度の自動選択」行](https://cdn.jsdelivr.net/npm/dsh-auto-effort@0.2.5/docs/menu-ja.png)

- **安い**：手動で強度を選ぶと、たいてい外します。低すぎればやり直しで余計にお金がかかり、高すぎればトークンを無駄にします。自動なら1メッセージあたりの追加コストはオフピークで約 `$0.0002`、ピーク時でも約 `$0.0004` だけです。
- **速い**：手動で選ぶと2クリックと2〜3秒かかります。低すぎる選択はやり直しになり、高すぎる選択は推論時間を無駄にします。自動なら1メッセージあたり約 **0.7 秒**しか増えません。
- **気楽**：メッセージごとに「low か max か」を悩む必要も、「あ、強度を間違えた」もありません。言いたいことを言えば、強度はそれについてきます。**不安ゼロ！**
- **コストが見える**：メニューの行に、この会話の実行回数・コスト・判定時間が出ます。プラグインのページには累計が出ます。
- **いつでも切り替え**：使いたくないときはオフに、使いたいときはオンに。

![プラグインのページと累計](https://cdn.jsdelivr.net/npm/dsh-auto-effort@0.2.5/docs/plugin-page-ja.png)

## 判定のしくみ

このプラグインは最新の DeepSeek モデルにつながります。会話を要約し、120文字以内のカードをバックグラウンドで保持します。メッセージを送るたびに、そのメッセージとカードを読み、4つの強度から1つを選びます。カードには会話が何をしていて何が残っているかが書かれているので、「はい、進めて」も文の短さではなく残りの作業で判定されます。

| 強度 | DeepSeek が選ぶ用途 | 実測例 |
|---|---|---|
| `off` | 雑談、確認、調べもの、設定の変更、コマンド実行 | 現在のディレクトリを一覧して |
| `low` | 小さな修正、名前の変更、整理、既存のパターンに合わせた適用 | この変数の名前を統一して |
| `high` | 分析、デバッグ、理由の説明、それなりの規模のコード | この方法が遅い理由を一緒に考えて |
| `max` | アーキテクチャ、選択肢の比較、多要素のトレードオフ、厄介なバグ | ログからこの断続的なメモリリークの根本原因を追って |

> DeepSeek は強度パラメータ（`low` / `high` / `max`、および思考オフの `off`）をドキュメントで定義していますが、**どの種類のタスクがどの強度に当たるかは示していません**。上の表は、人からの入力なしに DeepSeek の判定モデル自身が提案したものです。例はすべて実際の判定で試しています。

## コスト

プラグインは1メッセージにつき1回の判定と1回のカード更新を行います。判定は off・low・high・max のいずれか一語を返すだけなので、トークンはほとんど消費せず、所要時間は約0.7秒です。カードは120文字までなので、会話が長くなっても増えません。カードは返信のあとにバックグラウンドで書かれるため、待ち時間には加わりません。

| 1メッセージあたり | オフピーク | ピーク |
|---|---|---|
| 判定 + カード | 約 `$0.0002` | 約 `$0.0004` |

## インストール

3つの方法から1つ選んでください。

**1. DSH にインストールさせる** — 任意の会話でこれを送ります：

```
プラグイン dsh-auto-effort をインストールして
```

**2. コマンドライン**：

```
plugin_manager install_bundle dsh-auto-effort
```

**3. プラグインのページ** — サイドバーの**プラグイン**を開き、`dsh-auto-effort` を検索して**インストール**をクリックします。

`+ dsh-auto-effort` で始まる行が出れば成功です。

**プラグインをインストールまたは更新したら、DSH を再起動してください。**

## オンとオフ

**オン**

インストールした時点でオンです。新しい会話はすぐに自動選択が始まり、**すでに開いていた会話は DSH を再起動すると始まります。**

**オフ**

- モデルメニューで**強度の自動選択**をオフにすると、この会話だけに効きます。
- 強度を手動で選ぶと、その会話の自動選択もオフになります。
- プラグインのページでプラグインをオフにすると、すべての会話で自動選択が止まります。

## 設定

通常、ここは何も編集する必要はありません。以下は調整とトラブルシューティング用で、既定値のままでほとんどの人に合います。

| フィールド | 既定値 | 内容 |
|---|---|---|
| `enabled` | `true` | マスタースイッチ。オフにすると判定ロジックは一切読み込まれません |
| `mode` | `auto` | 新しい会話の既定値。`auto` はメッセージごとに判定し、`manual` は手動の引き継ぎのみ。メニューのスイッチは今いる会話だけを変えます |
| `levels` | `["off","low","high","max"]` | 自動モードが使用できる強度 |
| `judgeModel` | `deepseek-flash` | 判定に使うモデル。空欄または `model` ならこの会話自身のモデルで判定します |
| `timeoutMs` | `3000` | 判定のタイムアウト。タイムアウト時は現在の強度のままにします |
| `defaultLevel` | `null` | 判定に失敗したときのフォールバック強度。`null` は現在の強度を維持 |
| `requireMaxForUpgrade` | `false` | 既定はオフで、自動が最上位の `max` まで選べます。オンにすると自動は `high` までになり、`max` は手動のみ |
| `logFile` | `null` | ログのパス。`null` なら `~/.dsh/auto-effort.log` |
| `cardInputChars` | `600` | カード作成時に返信から読み取る文字数。小さくすると安くなりますが、精度は落ちることがあります |
| `cardMaxChars` | `120` | カード本文自体の上限文字数。小さくすると安くなりますが、精度は落ちることがあります |
| `debug` | `false` | 詳細ログ。判定の生の出力も含みます |

## 実行中にメッセージを送ると

**設定 → 一般 → 実行中の送信動作**は、返信がまだ書かれている間に送ったメッセージの扱いを決めます：

- **指示を変更** — 実行中のターンに合流し、そのターンの強度を引き継ぎます。
- **キュー** — 通常のメッセージとまったく同じように扱われます。

## うまく動かないとき

1. プラグインのページ（**プラグイン → インストール済みプラグイン**）で、プラグインが**有効**になっているか確認します。
2. インストールしたときすでに開いていた会話なら、DSH を一度再起動します。
3. モデルメニューの**強度の自動選択**がまだオンか確認します。強度を手動で選ぶと、この会話だけでオフになります。
4. `~/.dsh/auto-effort.log` のログを見ます。メッセージごとに `turn N judging …` の行が書き込まれます。
5. ターンが API エラーになった場合、または判定が3回連続で失敗した場合、プラグインはこの会話を一時停止し、入力欄の上に出るバーに理由が表示されます。バーの**もう一度オンにする**を押すか、スイッチをオフにしてからもう一度オンにすれば復帰します。再起動は不要です。

## アンインストール

**プラグイン → インストール済みプラグイン → dsh-auto-effort → アンインストール。** 判定が止まり、追加された設定も削除されます。

## 開発

- ソース：`index.js`（ホスト側）、`client.js`（モデルメニューのスイッチと一時停止バー）、`judge.js`（2回の判定呼び出し）、`config.js`（依存なしの検証）、`schema.js`（設定スキーマ）、`stats.js` と `server.js`（数字の裏側にあるローカルのコストカウンターと会話ごとのスイッチ）。
- ローカルディレクトリからのインストール（`install_bundle <dir>`）は開発者向けの方法で、一般のユーザーはこの方法ではインストールしません。プラグインを削除する前に、そのディレクトリをバックアップしてください。
- `npm test` は3つのオフラインスイートを実行します。設定・解析・タイムアウト、引き継ぎと会話ごとのスイッチの配線（一時停止バーの状態を含む）、そしてループバックのサイドカーです。
